# 灵犀栈论文复现档案

本仓库保存当前项目的源码、测试、部署与分析脚本、冻结配置和复现说明。原始实验记录、历史版本、全部工作文件及 Docker/WSL 虚拟磁盘保存在用户自己的夸克网盘加密完整归档。

## 复现顺序

1. 使用归档版本对应的提交和 `SOURCE_MANIFEST.json` 核对代码。
2. 从网盘取得同版本的全部 `part-*.zip`、`PACKAGE_MANIFEST.json`、`restore_backup.py` 与读取说明；解密文件由所有者单独保管，不在仓库或网盘档案中。
3. 运行恢复脚本到全新目录。F_PROJECT 为原项目工作树，E_REBUILDS 为所有实验副本，F_DOCKER_DATA/E_WSL_DISTROS 为停机保存的共享虚拟磁盘。
4. 先做完整文件 SHA-256 验收，再使用恢复后的 `LOCAL_DEPLOYMENT.md`、实验目录的 README 和关账复现说明选择原始冻结入口。
5. 离线重算保存记录中的统计表和中文图表。原有缺失、失败及 UNKNOWN 必须保留；真实模型重跑会产生费用，外部模型输出与计时不承诺逐字或逐毫秒相同。

## 代码与完整档案的关系

GitHub 不是完整数据备份。大型数据、审计原文、模型响应、私有账单、凭证、旧 Git 历史、镜像和二进制材料在加密归档中。恢复后的原始工作文件保持原字节及原路径映射；当前仓库选择了适合版本管理的源码与小配置。被安全规则排除的代码见 `SECURITY_EXCLUSIONS.json`，其原件仍在加密档案中。

当前实际工作布局为 `final-submit/src` 和 `deployment`。原 GitLink 历史没有完整收录这些新增文件，因此本次从当前工作文件新增归档版本，而不把旧 Git 历史当作当前工作树。

## 安全与范围

`.env` 只在加密档案中，仓库仅有 `.env.example`。尚未公开论文时保持本仓库私有。归档和上传不删除、移动、覆盖原项目文件。
